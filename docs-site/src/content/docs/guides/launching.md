起動ボタン右の **▼** から開くモーダルで、起動方法を選べます。

| 項目 | 選択肢 | 記憶される場所 |
|------|--------|----------------|
| アプリ | Claude Code / opencode / OpenAI Codex | ブラウザの `localStorage` (次回以降の既定) |
| 表示 (opencode のみ) | ⌨ ターミナル / 💬 チャット | 同上 |
| 起動モード | 通常起動 / 🔒 サンドボックスで起動 | 同上 |
| GPG署名を使う | on/off (既定 off) | `localStorage` に**ディレクトリ単位**で |
| ssh-agentを転送する | on/off (既定 off) | 同上 |

サンドボックス・GPG・ssh-agent の詳細は [サンドボックス](/ccserver/sandbox/overview/) を参照してください。「アプリ」と「起動モード」のどちらの項目をクリックしても、選んだ内容で即座に起動します。

新規セッションの既定アプリ・サンドボックス設定は `~/.config/ccserver/sandbox.config.json` (詳細は [設定ファイル](/ccserver/sandbox/configuration/)) でサーバー全体の初期値を決められますが、上記モーダルで一度でも明示的に選んだ後はブラウザ側の記憶が優先されます。

**サーバーにインストールされていない CLI は選択できません**: ccserver は起動モーダル表示時にサーバー側の実行ファイル解決 (PATH・サーバーの node バイナリディレクトリ・`~/.local/bin`・アプリ別ディレクトリ) を確認し、見つからないアプリはグレーアウトされます (ツールチップ「サーバーに未インストール」)。既定アプリが未インストールの場合も、利用可能なアプリへ自動で切り替えます。何らかの経路で未インストールのアプリが指定された場合 (例: 予約プロンプトの自動再開)、サーバーは `Cannot launch: <app> is not installed on this server (searched ...)` という明示エラーを返します。インストール/アンインストールした場合はブラウザを再読込すれば反映されます。

## opencode を選んだ場合の挙動の違い

- **クリップボード同期 (OSC 52)**: opencode がターミナルに書き込む OSC 52 シーケンスをブラウザが解釈し、システムクリップボードへ反映します (xterm.js は OSC 52 を無視するため、ccserver 側で処理)。
- **TUI ネイティブスクロール**: opencode は独自の代替画面バッファでスクロールするため (xterm.js 自体のスクロールバックは効きません)、マウスホイール/タッチドラッグは合成ホイールイベントとして、ターミナル下部のスクロールボタンは opencode のメッセージスクロールキー (PageUp/PageDown, Ctrl+G/Ctrl+Alt+G) として中継されます。
- **列数の確保**: 狭い画面 (スマホ等) では、opencode のプロンプト表示 (agent · model · provider 行) が折り返して画面の大半を占領しないよう、68 列を下限にフォントサイズを自動で縮小します。
- Usage ボタンは Claude Code の `/usage` 専用のため、opencode セッションでは非表示になります。

## opencode のチャット表示

opencode 2.0 以降がサーバーに入っていると、起動モーダルの「表示」で **💬 チャット**を選べます。opencode の TUI を xterm.js で描く代わりに、一般的な Web チャットの画面で会話します。

- **起動中の表示**: 会話が始まるまで、いま何をしているかを段階ごとに出します (サンドボックスを準備中 → VM 起動中 → VM セットアップ中 → opencode を起動中 → セッションを作成中)。VM の段は QEMU バックエンドで VM を新しく起動するときだけ出ます。失敗した段は ✖ になり、原因 (opencode の最後のエラー出力など) と起動ログが自動で開きます。
- **会話**: 応答の Markdown (コードブロックにはコピーボタン)、思考過程 (折りたたみ)、ツール呼び出しのカード (edit / write は差分表示) がストリーミングで表示されます。
- **許可・質問**: opencode が許可を求めると入力欄の上にカードが出て、「今回のみ許可 / 常に許可 / 拒否」で答えます。質問フォームも同じ場所に出ます。タブを見ていないときはブラウザ通知が届きます (通知ブリッジが有効なら、Discord / Web Push にも流れます)。
- **入力**: Enter で送信、Shift+Enter で改行 (タッチ端末では Enter は改行で、送信はボタン)。`/` で始めるとコマンドを補完します。実行中に送ったメッセージはキューに入り、■ ボタン (または Esc) で実行を止められます。エージェント・モデル・effort (推論の強さ。モデルが対応しているときだけ出ます) は入力欄の下で切り替えられます。
- **再接続・再開**: ブラウザを閉じても会話はサーバー側で続きます。開き直すと続きから表示され、opencode が終了していた場合は「再起動して続きから」で同じディレクトリの直近の会話を再開します。予約プロンプトもチャットセッションへそのまま送られます。
- セッション一覧のアクティビティ表示は、画面ではなく opencode のイベント (実行中 / 応答済み / 回答待ち) から決まります。

仕組みとしては、セッションの中で `opencode serve` を起動し、ccserver が認証付きで中継します (`/api/oc/<session id>/…`)。opencode のパスワードはセッションごとに生成され、ブラウザには渡りません。中継するのはチャットに必要な API だけで、opencode の PTY / シェル / 設定変更などの API は通しません。

制限:

- opencode 1.x では選べません (チャット表示が使う `opencode serve` の v2 API が無いため)。
- Auto-Y (自動承認) はチャット表示にはありません。

## OpenAI Codex について

- モデル入力と `codex resume` / `codex resume --last` を利用できます。Codex の TUI 出力からセッション ID は推測しません。
- Codex の永続 `codex mcp add` は自動実行しません。ccserver は起動単位の `-c mcp_servers.<name>=...` で MCP を注入するため、`~/.codex/config.toml` を変更せずに利用できます。
- サンドボックスではプロジェクト単位の永続 HOME 内に `~/.codex` を保持します。Codex 自身の sandbox/approval policy は ccserver 側から無条件に緩和しません。

## タブのアクティビティ表示 (緑 / 黄 / 赤)

セッション一覧の各行に、そのセッションのエージェントが**いまどの程度動いているか**を示す点が付きます。

| 点 | 形 | 意味 |
|---|---|---|
| 緑 | 中空 | **待機中** — エージェントは動いておらず、あなたの入力を待っています |
| 黄 | 半分塗り | **低活動** — 稼働中ですが画面はほとんど動いていません (Thinking 中、長いツール呼び出しなど) |
| 赤 | 塗りつぶし | **稼働中** — 出力が流れています |

点にカーソルを合わせると、判定の根拠と実測値 (例: 「稼働中 — 出力が流れている / 稼働中の表示を検出 / 画面更新 31.5 行/秒」) が出ます。色が区別できない環境でも読めるよう、レベルごとに**形**を変えてあり、状態語は行の読み上げ名 (aria-label) にも入ります。シェルセッションには出ません (中にエージェントが居ないため)。

判定の要点:

- **緑は時間だけで決めていません。** 各 CLI が稼働中だけフッターに出す中断キーのヒント (Claude Code は `esc to interrupt`、opencode は `esc interrupt`) が**無いこと**、画面が静止していること、直近に何も描画されていないことの**3つすべて**を満たしたときだけ緑になります。スピナーが回っている間は緑になりません。
- **赤と黄の境目**は「1 秒あたりに書き換わった画面の行数」です。スピナーは同じ 1 行を書き直し続けるだけなので黄、応答やツール出力が流れていれば赤になります。行数は端末幅の影響を受けるため、判定時に基準幅へ正規化しています。
- **ちらつき防止**: 赤に入る閾値と黄に戻る閾値を分け、さらに昇格は短い窓・降格は長い窓で見ています。ターンの途中で一瞬静かになっても赤のまま保たれ、ターンが終われば数秒で戻ります。
- **稼働中表示が未検証の CLI** (現状 OpenAI Codex) は上記のヒントが実機で確認できていないため、画面の動きだけで判定しています。点は彩度を落として表示され、ツールチップにその旨が出ます。これらのアプリでは「静止している」と判断するまでの待ち時間を長めに取り、思考中を誤って緑にしにくくしています。

### この表示が保証すること・しないこと

これはターミナルの画面を読んでいる表示です。分かるのは**アプリが描いたもの**だけなので、保証は正確には次の範囲です。

> **緑 = そのアプリが中断キーを表示しておらず、画面が一定時間変化しておらず、直近にも何も描画されていない。**

行儀のよい CLI ではこれは「ターンが終わった」と同じ意味になり、それがこの機能の目的です。一方で、これは**プロセスの状態についての主張ではありません**。自分の出力を制御できるエージェントは、フッターを消して黙っていれば作業中でも緑に見せられますし、細かく出力を出し続ければいつまでも非緑にできます。画面を見る限り「静かな端末」と「静かなエージェント」は同じ絵なので、これは画面をより注意深く読んでも解決できません (解決するなら TUI の外側、プロセスやプロトコルの信号が要ります)。

したがってこの表示は、**自分のタブを眺めている人間のための目安であって、セキュリティ境界ではありません。**権限に関わる判断をこの色で決めないでください。オーケストレーター側の手順にも同じ注意が書いてあります。

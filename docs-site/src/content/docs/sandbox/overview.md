「🔒 サンドボックスで起動」([起動ガイド](/ccserver/guides/launching/) 参照) を選ぶと、Linux の `bwrap` でファイルシステムを制限して起動します。選択したプロジェクトと必要な CLI 設定だけが見え、隣接する他プロジェクトは見えません。macOS ではこのサンドボックス機能は利用できません。

サンドボックス内で Docker を使う場合は、rootless dockerd を起動します。`rootlesskit` の内側で `bwrap` を動かすため、`docker run -v ...` からもサンドボックス外のファイルには到達できません。必要なホスト側ツールや設定は [要件](/ccserver/getting-started/requirements/) を参照してください。

## サンドボックスの再利用 (永続 HOME)

既定ではサンドボックスの `HOME` はプロジェクトごとに永続化されます (`persistentHome`、既定 `true`)。保存先は `~/.local/share/ccserver-sandbox/home/<プロジェクト>` です。セッション中にインストールしたツール、キャッシュ、シェル設定は次回以降にも引き継がれます。隣接する他プロジェクトは見えません。

サンドボックス内の `/tmp` も永続 HOME 配下 (`.ccserver-tmp`) へプロジェクトごとに bind されるため、そこに展開したツールやキャッシュも引き継がれます。`persistentHome: false` の場合は HOME と `/tmp` が毎回初期化されます。

サンドボックスを起動するとき、前回の永続 HOME があれば再利用ダイアログが表示されます。

- **使用する**: 前回の永続 HOME を引き継ぎます。
- **新規作成**: 前回の永続 HOME を破棄して空の状態から始めます。利用中のセッションがある場合は選択できません。
- **キャンセル**: 何もせず閉じます。

`~/.config/ccserver/sandbox.config.json` で `"persistentHome": false` を指定すると、新しいセッションで永続 HOME を使わなくなります。既存データをリセットするには `~/.local/share/ccserver-sandbox/home/` 内の該当ディレクトリを削除してください。

:::caution[セキュリティノート]
永続 HOME はサンドボックスから書き込み可能なホスト上のディレクトリです。セッションが `.bashrc` などを仕込むと、同じプロジェクトの次回セッションで実行される可能性があります。機密プロジェクトで利用する場合はこの点を考慮してください。
:::

## ネットワーク隔離

ネットワーク隔離は qemu バックエンド専用です。qemu セッションの VM のネットワークは、ホスト側の Go ブローカー (ccserver-netbroker) がユーザー空間で丸ごと処理し、ブローカーを経由しない通信経路はありません。セッションは常に open で起動し、稼働中は 🌐 トグルで enforce (許可リストのみ) と open (一時的に全通信を許可) を切り替えられます。bwrap バックエンドではネットワークを隔離せず、通常どおり外部へ通信できます。`gitBroker` の通信はホスト側で行われるため、この設定の対象外です。

## 設定ページ

ディレクトリブラウザのヘッダー右端にあるスパナ (🔧) から設定タブを開けます。作成済みサンドボックスの一覧では、プロジェクトパス、表示ラベル、git remote、最終使用時刻、使用容量を確認し、永続 HOME と Docker データを削除できます。利用中のサンドボックスは削除できません。

サンドボックスの起動オプション、GPG 署名用 gpg-agent の転送、SSH agent の転送については [設定ファイル](/ccserver/sandbox/configuration/) と [認証情報の受け渡し](/ccserver/sandbox/credentials/) を参照してください。

title: コミット署名
description: サンドボックスのコミットをホストの署名用サブキーで署名する仕組みと、鍵の準備・運用手順
---

サンドボックスには署名鍵を渡さず、コミットはホストが署名します。サンドボックス側の仕組みと、どのコミットなら署名されるかは [認証情報の受け渡し](/ccserver/sandbox/credentials/#コミット署名-ホスト側で署名) を参照してください。このページでは、ホストに置く鍵の準備と運用を説明します。

## 鍵の置き場所

鍵はホスト専用の GNUPGHOME (既定 `~/.local/share/ccserver/signing-gnupg`、未移行の環境では `~/.local/share/ccserver-sandbox/signing-gnupg`、環境変数 `CCSERVER_COMMIT_SIGNING_GNUPGHOME` で変更可) に置きます。運用者自身の `~/.gnupg` は使いません。この GNUPGHOME がサンドボックスに渡ることはありません。

推奨は、**手元のマスター鍵から切り出した署名用サブキーだけ**を置く構成です。主鍵の秘密鍵はホストに置かないので、ホストが侵害されても失うのは失効できるサブキー 1 本で済みます。

## サブキーの準備 (推奨)

マスター鍵のある手元の環境で行います。

```sh
# 1. 署名用サブキーを追加する (有効期限は1年程度を推奨)
gpg --quick-add-key <主鍵のフィンガープリント> ed25519 sign 1y

# 2. 追加したサブキーの ID を確認する
gpg --list-secret-keys --with-subkey-fingerprint <主鍵のフィンガープリント>

# 3. そのサブキーだけを書き出す (末尾の ! はこのサブキーに限定する指定)
gpg --armor --export-secret-subkeys <サブキーID>! > signing-subkey.asc
```

サブキーにはパスフレーズを付けておいてください (主鍵と同じパスフレーズで書き出されます。分けたい場合は書き出す前に一時的な GNUPGHOME に import して `gpg --passwd` で変更します)。

ホストへの登録は次のどちらかで行います。

- ホストのシェルで `node server/cli/commit-signing-key.js import signing-subkey.asc` を実行する (サーバー停止中でも可)
- 設定 > コミット署名 で書き出した内容を貼り付ける

登録後は `signing-subkey.asc` を削除してください。

## マスター鍵が無い場合

設定 > コミット署名 の「このホスト専用の鍵を生成」で、証明用の主鍵と署名用サブキー (有効期限1年、パスフレーズ必須) を生成できます。この場合は主鍵の秘密鍵もホストに置かれるため、設定画面に注意が表示されます。

鍵が登録されていないホストでは、署名ありの起動は拒否されます。署名なしの起動はそのまま使えます。

## GitHub への登録

設定 > コミット署名 の公開鍵 (または `node server/cli/commit-signing-key.js export-public` の出力) を、GitHub の Settings > SSH and GPG keys > New GPG key に登録します。公開鍵にはサブキーも含まれます。サブキーを追加・延長・失効したときは登録し直してください。

## ロック解除

鍵は起動時やサーバー再起動時にロック状態から始まります。パスフレーズは鍵専用の gpg-agent にだけキャッシュされ、ロックするとエージェントごと破棄されます。

- 上部バーの「署名鍵ロック中」ボタン、承認バナーのロック解除依頼、設定画面のいずれかからパスフレーズで解除します。
- パスキーログイン (`CCSERVER_AUTH_MODE=passkey`) では、パスフレーズを PRF 対応パスキーで暗号化して保存しておき、タップで解除できます (設定 > コミット署名 の「パスキーでロック解除」)。登録にはパスフレーズの入力が必要です。鍵を差し替えると登録は無効になります。
- パスキーログインでは、有効なログインセッションが 1 つも無くなると自動でロックされます。

## 有効期限の延長と失効

- **延長**: 手元のマスター鍵で `gpg --quick-set-expire <主鍵のフィンガープリント> 1y <サブキーのフィンガープリント>` を実行し、サブキーを書き出し直してホストに登録し直します (先に設定画面か `commit-signing-key.js delete --yes` で古い鍵を削除してください)。GitHub の公開鍵も更新します。
- **失効**: ホストの侵害が疑われるときは、手元で `gpg --edit-key <主鍵>` → `key <番号>` → `revkey` でサブキーを失効させ、公開鍵を GitHub に登録し直したうえで、ホストの鍵を削除します。設定 > コミット署名 の「最近の署名」で、そのサブキーで署名したコミットを確認できます。
